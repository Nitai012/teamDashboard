# מפת התפתחות הצוות

כלי לרש״צ לפיתוח החיילים בצוות: כל חייל ממקם את עצמו על משושה של שישה צירים, המיקומים נשמרים עם תאריך כדי לראות התקדמות, וטבלת מקצועיות מראה מי מקצועי במה, מתי הוא משתחרר ואת מי כדאי להכשיר במקומו.

## מה יש בפנים

- **הצוות**: ממוצע הצוות על המשושה, כמה חיילים מעודכנים, מי משתחרר בחצי השנה הקרובה, והציר שהכי צריך לחזק.
- **דף חייל**: מיקום עצמי בגרירה או בסרגלים, ציר שישי אישי שכל חייל בוחר (Networking, ניהול, סקרנות טכנולוגית ועוד, או טקסט חופשי), יעד לתקופה הקרובה, היסטוריה עם השוואה על המפה, וגרף מגמה לכל ציר.
- **מקצועיות ושחרורים**: טבלה של חיילים מול תחומים, ממוינת לפי תאריך שחרור. לכל תחום מוצג כמה חיילים עצמאיים יש היום וכמה יישארו בסוף אופק התכנון (3 חודשים, חצי שנה או שנה). תחום שהידע בו עוזב מסומן באדום, ולצידו רשימת מועמדים להכשרה.
- **גיבוי**: הורדת גיבוי JSON, ייצוא לאקסל (CSV) ושחזור, כולל טעינת גיבוי מהגרסה הקודמת של העמוד.
- מותאם לטלפון (ניווט תחתון, חלונות כגיליון תחתון), מצב כהה ובהיר, ואפשר להוסיף למסך הבית.

## הרצה מקומית

צריך Git ו־Node.js בגרסה 22.22 ומעלה. בודקים עם `node -v`, ואם הגרסה ישנה מתקינים LTS מ־[nodejs.org](https://nodejs.org).

```bash
git clone https://github.com/Nitai012/teamDashboard.git
cd teamDashboard
corepack enable
pnpm install
pnpm first-run
pnpm dev
```

`pnpm first-run` שואל בטרמינל על סיסמה לכניסה (הקלדה מוסתרת, פעמיים), ויוצר לבד את קובץ ההגדרות `.env` עם ה־hash של הסיסמה ומפתח אקראי. בסוף הוא מציע להוסיף צוות דוגמה. אין צורך לערוך שום קובץ ידנית.

אחרי `pnpm dev` פותחים את http://localhost:5173 ונכנסים עם הסיסמה שבחרת. עוצרים עם Ctrl+C. כדי לשנות סיסמה מריצים שוב `pnpm first-run`.

### בדיקה מהטלפון

```bash
pnpm serve
```

הפקודה בונה הכל ומריצה שרת אחד בפורט 3000. בטלפון שמחובר לאותה רשת Wi‑Fi פותחים `http://<כתובת-ה-IP-של-המחשב>:3000`. במק מוצאים את הכתובת עם `ipconfig getifaddr en0`.

## הרצה עם Docker

```bash
cp .env.example .env
docker compose run --rm app node dist/scripts/hash-password.js
```

מעתיקים את השורה שמתחילה ב־`scrypt:` לשדה `ADMIN_PASSWORD_HASH` בקובץ `.env`, ומכניסים ל־`SESSION_SECRET` לפחות 32 תווים אקראיים (למשל הפלט של `openssl rand -base64 48`). אחר כך:

```bash
docker compose up -d --build
```

האפליקציה עולה בפורט 3000, והשרת מגיש גם את צד הלקוח מאותה כתובת. הנתונים נשמרים ב־volume בשם `team-radar-data`.

## משתני סביבה

| משתנה                 | ברירת מחדל           | הסבר                                                                                     |
| --------------------- | -------------------- | ---------------------------------------------------------------------------------------- |
| `ADMIN_PASSWORD_HASH` | חובה                 | hash של סיסמת הכניסה, מ־`pnpm hash-password`                                             |
| `SESSION_SECRET`      | חובה                 | לפחות 32 תווים אקראיים לחתימת עוגיית ההתחברות                                            |
| `COOKIE_SECURE`       | `true` בפרודקשן      | `true` כשהאתר עובד ב־HTTPS. ב־HTTP רגיל ברשת מקומית צריך `false`, אחרת ההתחברות לא נשמרת |
| `TRUST_PROXY`         | `false`              | `true` כשהאפליקציה יושבת מאחורי reverse proxy                                            |
| `PORT`                | `3000`               | פורט השרת                                                                                |
| `DATABASE_PATH`       | `data/team-radar.db` | קובץ ה־SQLite                                                                            |
| `SESSION_TTL_HOURS`   | `336`                | כמה זמן ההתחברות תקפה                                                                    |
| `WEB_DIST_PATH`       | ריק                  | תיקיית הבנייה של הלקוח שהשרת יגיש (מוגדר אוטומטית ב־Docker)                              |

## העברת נתונים מהגרסה הקודמת

בעמוד הקודם: **הגדרות וגיבוי ← הורדת גיבוי (JSON)**. כאן: **הגדרות ← בחירת קובץ גיבוי**. החיילים, רמות המקצועיות, סימוני ההכשרה, הציר האישי והמיקומים העצמיים עוברים. הערכות רש״צ מהגרסה הקודמת לא מועברות.

## אבטחה

- כל ה־API מאחורי התחברות. הסיסמה נשמרת כ־hash של scrypt, ונבדקת בהשוואה בזמן קבוע.
- ההתחברות היא עוגייה חתומה, `httpOnly` ו־`SameSite=Strict`, כך שאתר אחר לא יכול לשלוח בקשות בשם המשתמש.
- ניסיונות התחברות מוגבלים ל־5 בדקה.
- כותרות אבטחה (CSP ועוד) דרך helmet. הגופנים ארוזים עם האפליקציה, כך שאין תלות ב־CDN וזה עובד גם ברשת סגורה.
- ייצוא ה־CSV מנטרל ערכים שאקסל היה מריץ כנוסחה.
- הכלי מיועד למידע פיתוח אישי. **אין להכניס אליו מידע מסווג.**

## API

כל הנתיבים תחת `/api`, ומחייבים התחברות חוץ מ־`/health` ו־`/auth/login`.

| נתיב                                                                                  | פעולה                                      |
| ------------------------------------------------------------------------------------- | ------------------------------------------ |
| `POST /auth/login` · `POST /auth/logout` · `GET /auth/session`                        | התחברות                                    |
| `GET/POST /members` · `GET/PATCH/DELETE /members/:id`                                 | חיילים                                     |
| `DELETE /members/examples`                                                            | מחיקת נתוני הדוגמה                         |
| `PUT /members/:id/skills/:skillId`                                                    | רמה וסימון הכשרה בתחום                     |
| `GET/POST /skills` · `PATCH/DELETE /skills/:id`                                       | תחומים (שינוי שם לשם קיים מאחד את התחומים) |
| `GET /assessments` · `PUT /members/:id/assessments/:date` · `DELETE /assessments/:id` | מיקומים, אחד ליום לכל חייל                 |
| `GET/PUT /settings`                                                                   | שמות הצירים                                |
| `GET /backup` · `GET /backup/csv` · `POST /backup/import`                             | גיבוי, ייצוא ושחזור                        |
